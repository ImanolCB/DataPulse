# Constitución de DataPulse

## 1. Objetivo
Construir un dashboard de análisis de ventas mientras el usuario aprende los fundamentos de desarrollo de software.

## 2. Aprendizaje primero
Las decisiones técnicas deben favorecer la comprensión, la práctica y la capacidad del usuario para mantener el proyecto por sí mismo.

## 3. Desarrollo incremental
Cada cambio debe tener un objetivo concreto, un alcance limitado y un criterio de aceptación verificable.

## 4. Simplicidad
Se prefiere la solución más sencilla que satisfaga los requisitos actuales. No se incorporan abstracciones, dependencias o patrones sin una necesidad demostrable.

## 5. Autorización
El agente no puede implementar, modificar archivos, instalar dependencias ni realizar operaciones destructivas sin autorización explícita del usuario.

## 6. Arquitectura evolutiva
La arquitectura debe introducirse cuando los requisitos la justifiquen. No se anticipan capas, servicios o tecnologías de fases futuras.

## 7. Calidad
El código debe ser legible, mantener responsabilidades claras, gestionar errores previsibles y poder validarse.

## 8. Veracidad
Los datos ficticios deben identificarse como tales. Las pruebas y validaciones solo se declaran ejecutadas cuando existe evidencia de su ejecución.

## 9. Trazabilidad
Los requisitos, decisiones, tareas y resultados importantes deben mantenerse coherentes entre especificación, plan, tareas y código.

## 10. Gestión de cambios
Los cambios de alcance o arquitectura deben explicarse y aprobarse antes de implementarse.

## 11. Progresión tecnológica
Se utilizará inicialmente HTML, CSS y JavaScript nativo. Java, Spring Boot, SQL y las tecnologías posteriores se incorporarán según el roadmap y cuando el usuario esté preparado.
